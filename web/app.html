Help: what everything means

  

    
Point at a bar, a speed, a verdict or a score in the list to see a short explanation with that model's own numbers. Press ? to open this window, Esc to close it.


    
The memory bar

    
The bar shows if a model fits in your graphics card's memory (VRAM). The whole bar is the VRAM you can use for models (your VRAM minus "Kept for Windows").

    

      
Purple
The part that sits in VRAM: model file, KV cache and engine together. Fast.

      
Orange stripes
The model does not fit in VRAM. The rest goes to system RAM, which is about 10 times slower, so the model runs slower. The stripes are a warning sign, not to scale: the numbers below the bar give the real sizes, for example "3.2 GB VRAM + 75.0 GB RAM".

      
Empty part
VRAM that stays free.

    

    
The big bar in the detail panel (tab Overview) splits it further:

    

      
Model file
The weights of the model (the .gguf file).

      
KV cache
Memory for the context (the text the model remembers). It grows with "Context length". KV cache Q8 or Q4 makes it smaller.

      
Engine + other
Buffers of llama.cpp / LM Studio.

      
Thin line
Where your VRAM ends, when the model is bigger than VRAM.

    


    
Verdicts and "Runs on"

    

      
Runs well
Fits fully in VRAM with room to spare.

      
Runs, but tight
Fits in VRAM, but with little room left. A longer context or another program can push it over.

      
Runs, but slower
Part of the model runs from system RAM, or there is no GPU.

      
Won't fit
VRAM and RAM together are too small.

      
GPU
Everything in VRAM.

      
CPU+GPU
Part in VRAM, part in system RAM.

      
MoE offload
A "mixture of experts" model: it has many experts but uses only a few per word. The unused experts wait in system RAM, so even a very big model can run, more slowly.

      
CPU
No GPU: everything from system RAM.

    

    
The four tiles above the list count each verdict. Click a tile to show or hide those models.


    
The other columns

    

      
Size
Number of parameters: B = billion, M = million. More parameters usually means smarter, but bigger and slower.

      
Best file
The quantization (file version) llmfit picks for this PC. Q8_0 is close to the original quality; Q6, Q5, Q4, Q3, Q2 are smaller and faster, but less precise. F16/BF16 = original size.

      
Speed
Tokens per second (a token is about ¾ of a word). A range, because it is an estimate. About 7 tok/s is reading pace.

      
Score
llmfit's match for this PC, 0 to 100, built from quality, speed, fit and context.

    


    
Labels and icons

    

      
 Vision · Tool use · Reasoning
The model can read images · call functions (for agents) · think step by step. "(from the model name)" means the name says so, not the model card.

      
NEW
Released in the last 60 days.

      
MTP
Multi-token prediction: the model has extra layers that guess the next few tokens at once. A runtime that supports it (in LM Studio: speculative decoding, MTP) can answer faster with the same quality. TensorTailor reads it from the GGUF header of the file (tab Files), else from config.json, else from the name ("from the name"). In My models, "MTP on/off" is LM Studio's own setting for a loaded model; "MTP in file" comes from the header of your own model file. To read your files, My models asks once for LM Studio's models folder (the same folder as for Downloads); TensorTailor matches each model to its file by size and reads only the start of the file (layers, maximum context, MTP). For models that TensorTailor added itself ("live" or "from LM Studio"), the header also gives the KV cache size (KV heads, head size, and how many layers keep the whole context), so llmfit counts it exactly instead of roughly. When LM Studio does not name the quant, the file name tells it.

      
live
Not in llmfit's list: fetched live from Hugging Face (Tools → Catalog, or a pasted link). Models in your LM Studio that llmfit's list does not have are fetched like this by themselves, so the filter "Already in LM Studio" shows all of them.

      
from LM Studio
In your LM Studio, but not in llmfit's list, and llmfit could not read it from Hugging Face. The row is made from what LM Studio and the model file's header say (parameters, quant, layers, context); llmfit's formulas give the verdict. Rougher than a model from llmfit's list.

      
MoE
Mixture of experts (see MoE offload).

      
upgrade
Only runs well with the upgrade you switched on under "What if I upgrade?".

      
measured
The speed comes from real measurements on similar hardware, not from an estimate.

      
in LM Studio
You already have this model in LM Studio.

      
license
Not a plain open license (MIT, Apache): Llama, Gemma, non-commercial or research licenses have their own terms. Read them on the model page. The page carries Hugging Face's list of gated models from the day it was built (the weekly release makes a fresh one); without it, the label is a guess from the license name. When you open a model, TensorTailor also asks Hugging Face live if the repo is really "gated" (you accept the terms on Hugging Face first, and TensorTailor then needs your HF token to read the files) and remembers the answer for 7 days: the label then says gated (token needed), or stays license in grey (own terms, but no token needed). Many copies and fine-tunes are not gated. A repo with an open license can be gated too. The filter No token needed hides the gated models.

      
vLLM and others
The model needs another engine than llama.cpp; LM Studio on Windows cannot run it.

    


    
Your hardware and settings (left)

    

      
VRAM per GPU · Number of GPUs
Memory of one graphics card, and how many identical cards you have.

      
System RAM
Normal memory of the PC. Used when a model does not fit in VRAM.

      
Kept for Windows
VRAM that Windows and your screens use. Not available for models.

      
RAM speed
How fast system RAM is (GB/s). Sets the speed of the part that runs from RAM.

      
CPU cores
Used for the CPU part of a model.

      
Detect · Import…
Fill these in from the browser, or from a PowerShell line that reads your real hardware.

      
What if I upgrade?
Shows which models would run well with one more GPU or 128 GB more RAM (label "upgrade").

      
What is it for?
Show only models for general use, coding, reasoning, chat, images + text or embedding.

      
Context length
How much text the model keeps in mind. Longer context = bigger KV cache = more memory.

      
KV cache
F16 is normal. Q8 halves the KV cache, Q4 makes it about a quarter, with a small loss in quality. It changes the detail panel and the plan.

      
Filters
"Runs in LM Studio (llama.cpp)" and "Popular (10,000+ downloads)" are on by default. New or rare models can be hidden by them. Models that are already in your LM Studio always pass "Popular". Your choices on the left (filters, what it is for, context length, KV cache, sort and the four verdict tiles) are kept in this browser, also after a reload. Reset puts the filters back to the start values. Above the list, every active filter is a chip: click its × to remove it, Clear all to see every analysed model, Defaults for the start values. Your hardware is a short summary; Edit hardware opens the fields, Detect in browser and Import….

      
Search
Type a name or a publisher (for example bartowski). The line under the list shows how many matches your filters hide (Show all turns the filters off for this search). Search Hugging Face finds the publisher's models and models with the text in their name, and checks them with llmfit's own code (label live). Paste a Hugging Face link and press Enter to check one model.

    


    
The detail panel (right)

    

      
Top of the panel
The answer first: the verdict, the best file for this PC, the file you have in LM Studio (if any), and one action: Load in LM Studio… or Choose a file to download. ☆ Favorite stars the model. This part stays in view while you scroll.

      
Overview
Verdict, memory, speed, and "Which file fits?" for every quantization. When llmfit's planner (more safety room) rates the best file lower than the list, a yellow note says so and names the best file that runs well.

      
Files
The real files on Hugging Face with their SHA-256. Download saves a file into your folder and checks it.

      
Run
"LM Studio load settings for this PC": what to set in LM Studio's load dialog for this model (context length, GPU offload, flash attention, K/V cache, speculative decoding, remember settings), with the reason; point at a ? for what each setting does. Load in LM Studio with these settings (when the model is in LM Studio and its server is on) first shows what will be sent, then asks LM Studio to load it: context length, flash attention, KV cache on the GPU and MTP. LM Studio's API cannot set GPU offload and K/V cache quantization, so LM Studio keeps its own setting for those. A model that is loaded already is unloaded first; other loaded models stay, unless you tick the box to unload them. Below it: ready commands and settings for AI agents.

      
Plan
llmfit's planner: what hardware the model needs, which routes work, how many chats fit.

    


    
Views (top) and keys

    

      
Models · My models · Battle · Downloads
Click to switch, or press 1 to 4. Esc always brings you back to Models.

      
Favorites ★
Click the star next to a model (or press W) to make it a favorite. Only my favorites (filters) shows just those. My models shows the same stars for your LM Studio models that are matched to llmfit's list; click a star there to add or remove it too.

      
Tools (top right)
Catalog: where the list comes from, and "Fetch new models" from Hugging Face. Hugging Face token: for gated models (the dot on Tools is green when a token is set). About and licenses. Light or dark (key T).

      
HF token
Read-only Hugging Face token for gated models. It stays only in this browser tab.

      
Keys
/ search · ↑ ↓ (or j k) move · C select for compare · W favorite (star) · T light or dark · ? help.
