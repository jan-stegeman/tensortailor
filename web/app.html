Help: what everything means

  

    
Point at a bar, a speed, a verdict or a score in the list to see a short explanation with that model's own numbers. Press ? to open this window, Esc to close it. The list at the left jumps to a part; its search box shows only the rows that contain your words.


    
The memory bar

    
The bar shows if a model fits in your graphics card's memory (VRAM). The whole bar is the VRAM you can use for models (your VRAM minus "Kept for Windows").

    

      
Grey bar
The part that sits in VRAM: model file, KV cache and engine together. Fast. The number at the right of the line below it is how much of your usable VRAM that is.

      
Amber end
Less than 12 % of the usable VRAM stays free: it runs, but a longer context or other programs can push it over.

      
Orange stripes
The model does not fit in VRAM. The rest goes to system RAM, which is about 10 times slower, so the model runs slower. The stripes are a warning sign, not to scale: the numbers below the bar give the real sizes, for example "3.2 GB VRAM + 75.0 GB RAM".

      
Empty part
VRAM that stays free.

    

    
The big bar in the detail panel (tab Overview) splits it further:

    

      
Model file
The weights of the model (the .gguf file).

      
KV cache
Memory for the context (the text the model remembers). It grows with "Context length". KV cache Q8 or Q4 makes it smaller.

      
Engine + other
Buffers of llama.cpp / LM Studio.

      
Thin line
Where your VRAM ends, when the model is bigger than VRAM.

    


    
Verdicts and "Runs on"

    

      
Runs well
Fits fully in VRAM with room to spare.

      
Runs, but tight
Fits in VRAM, but with little room left. A longer context or another program can push it over.

      
Runs, but slower
Part of the model runs from system RAM, or there is no GPU.

      
Won't fit
VRAM and RAM together are too small.

      
GPU
Everything in VRAM.

      
CPU+GPU
Part in VRAM, part in system RAM.

      
MoE offload
A "mixture of experts" model: it has many experts but uses only a few per word. The unused experts wait in system RAM, so even a very big model can run, more slowly.

      
CPU
No GPU: everything from system RAM.

    

    
Above the list

    

      
Top picks for this PC
Three suggestions that follow your filters: Best overall, Highest quality and Fastest, each with its verdict, file and speed. View details opens the model; Add to battle puts it in Battle. Closed, they are one slim strip with the three names (click a name to open it); the arrow at its right, or the sparkle button next to Sort, shows them as cards; Hide folds the cards back into the strip.

      
The four tiles
The segments at the left of the toolbar count each verdict. Click one to show or hide those models; a hidden one is crossed out and grey.

      
Count line
At the right of the filter chips: how many models are shown, how many the tiles hide, how many llmfit analysed, and how long that took.

      
Filter chips
Every active filter is a chip: click its × to remove it. Clear all shows every analysed model; Defaults gives the start values.

      
Export CSV
The arrow-up button next to Sort: saves the shown list as a CSV file (for a spreadsheet).

      
Legend
The (i) button next to Sort: opens this help at "The memory bar".

      
Sort
The list next to the arrows icon: best match, fastest, smallest, largest, longest usable context, newest, most downloaded, or name.

    


    
The columns

    

      
Model
The name (↗ opens it on Hugging Face), its labels and icons (see below), the publisher and the number of parameters: B = billion, M = million. More parameters usually means smarter, but bigger and slower. The star makes it a favorite; the box selects it for compare or battle.

      
Best file
The quantization (file version) llmfit picks for this PC. Q8_0 is close to the original quality; Q6, Q5, Q4, Q3, Q2 are smaller and faster, but less precise. F16/BF16 = original size.

      
Memory
The memory bar (see above), with the memory the model needs.

      
Speed
Tokens per second (a token is about ¾ of a word). A range, because it is an estimate. About 7 tok/s is reading pace.

      
Verdict
How well it runs here, and where it runs (GPU, CPU+GPU, MoE offload, CPU).

      
Score
llmfit's match for this PC, 0 to 100, built from quality, speed, fit and context.

      
Chosen row
The model you clicked (or opened with Show or View details) has a purple tint and a glowing purple bar at its left edge; its details are on the right.

    


    
Labels and icons

    

      
 Vision
The model can read images (photos, screenshots). It does not make images.

      
 Tool use
The model can call functions, so AI agents can use it.

      
 Reasoning
The model thinks step by step before it answers. "(from the model name)" means the name says so, not the model card.

      
NEW
Released in the last 60 days.

      
MTP
Multi-token prediction: the model has extra layers that guess the next few tokens at once. In LM Studio, speculative decoding with MTP can then answer faster with the same quality. TensorTailor reads it from the GGUF header of the file (tab Files), else from config.json, else from the name ("from the name"). For the MTP labels in My models, see "My models" below.

      
in LM Studio
You already have this model in LM Studio.

      
live
Not in llmfit's list: fetched live from Hugging Face (Tools → Catalog, or a pasted link). Models in your LM Studio that llmfit's list does not have are fetched like this by themselves, so the filter "Already in LM Studio" shows all of them.

      
from LM Studio
In your LM Studio, but not in llmfit's list, and llmfit could not read it from Hugging Face. The row is made from what LM Studio and the model file's header say (parameters, quant, layers, context); llmfit's formulas give the verdict. Rougher than a model from llmfit's list. Its name is the Hugging Face repo of its folder when there is one; else it starts with lmstudio/: then no Hugging Face page is known, its ↗ link searches Hugging Face for the name, and it is counted apart from the live models (Tools → Catalog).

      
size uncertain
The name shows already-compressed weights that are not GGUF (EXL2/EXL3, bnb, AWQ, GPTQ, MLX, vllm, "9bit" …), or says far more parameters than llmfit counts (for example 27B in the name, 10.3B counted). llmfit then counted the compressed weights, so its memory and speed are too optimistic. These rows come after the others with the same verdict and are never a top pick; the Overview tab says why. Look for a GGUF copy of the original model instead.

      
gated
Gated on Hugging Face: accept the terms on the model page first, then set your Hugging Face token (the key button at the top right, or Tools → Hugging Face token) to download the files. A repo with an open license can be gated too.

      
license (grey)
Not a plain open license (MIT, Apache): Llama, Gemma, non-commercial or research licenses have their own terms. Read them on the model page. Not gated: the files download without a token.

      
license (orange)
The same kind of license, but not checked yet: the guess comes from the license name. Open the model and TensorTailor asks Hugging Face; the label then becomes gated or a grey license.

      
Where "gated" comes from
The page carries Hugging Face's list of gated models from the day it was built (the weekly release makes a fresh one). When you open a model, TensorTailor also asks Hugging Face live and remembers that answer for 7 days. Point at a label to see where its answer comes from. The filter No token needed hides the gated models.

      
MoE
Mixture of experts (see MoE offload).

      
upgrade
Only runs well with the upgrade you switched on under "What if I upgrade?".

      
measured
The speed comes from real measurements on similar hardware (llmfit's own community results), not from an estimate. Your own measurements on this PC are shown separately: see "My models: Measure".

      
vLLM and others
The model needs another engine than llama.cpp; LM Studio on Windows cannot run it.

    


    
Your hardware and settings (left)

    

      
VRAM per GPU · Number of GPUs
Memory of one graphics card, and how many identical cards you have.

      
System RAM
Normal memory of the PC. Used when a model does not fit in VRAM.

      
Kept for Windows
VRAM that Windows and your screens use. Not available for models.

      
RAM speed
How fast system RAM is (GB/s). Sets the speed of the part that runs from RAM.

      
CPU cores
Used for the CPU part of a model.

      
Detect · Import…
Fill these in from the browser, or from a PowerShell line that reads your real hardware.

      
What if I upgrade?
Shows which models would run well with one more GPU or 128 GB more RAM (label "upgrade").

      
What is it for?
Show only models for general use, coding, reasoning, chat, images + text or embedding.

      
Context length
How much text the model keeps in mind. Longer context = bigger KV cache = more memory.

      
KV cache
F16 is normal. Q8 halves the KV cache, Q4 makes it about a quarter, with a small loss in quality. It changes the detail panel and the plan.

      
Your choices are kept
Filters, what it is for, context length, KV cache, sort and the four verdict tiles are kept in this browser, also after a reload. Reset (Filters) puts the filters back to the start values. Your hardware is a short summary; Edit hardware opens the fields, Detect in browser and Import….

      
Search
Type a name or a publisher (for example bartowski). The line under the list shows how many matches your filters hide (Show all turns the filters off for this search). Search Hugging Face finds the publisher's models and models with the text in their name, and checks them with llmfit's own code (label live). Paste a Hugging Face link and press Enter to check one model.

    


    
Filters (left)

    

      
Language · Size
Only models for a language, or of a size (number of parameters).

      
Vision · Tool use · Reasoning
Only models with that skill (see the icons above). You can switch on more than one.

      
Runs in LM Studio (llama.cpp)
Only models that LM Studio can run. On by default. It also hides repos whose name shows already-compressed weights in another format (EXL3, bnb-4bit, AWQ, GPTQ, MLX, vllm …): LM Studio cannot load those as they are (label size uncertain).

      
Known GGUF download
Only models with a known GGUF copy on Hugging Face (the file type LM Studio uses).

      
Released in the last 60 days
Only new models (label NEW).

      
Only my favorites ★
Only the models you starred.

      
Already in LM Studio
Only the models you have in LM Studio (label "in LM Studio").

      
Open license (Apache, MIT)
Only models with a plain open license.

      
No token needed
Hides the models that are gated on Hugging Face (label "gated").

      
Fits fully in VRAM
Only models that run fully on the graphics card.

      
Popular (10,000+ downloads)
Only models with 10,000 or more downloads. On by default. New or rare models can be hidden by it; models in your LM Studio always pass.

    


    
The detail panel (right)

    

      
Top of the panel
The answer first: the verdict, the best file for this PC, the file you have in LM Studio (if any), and one action: Load in LM Studio… or Choose a file to download. The star button (☆) at the right stars the model as a favorite. Below the name: the labels, and one line with the facts (parameters, maximum context, license with "(gated)" or "(not gated)", release date, downloads). This part stays in view while you scroll; it shrinks to the name, the answer and the tabs.

      
Panel width
Drag the thin line at the left edge of the detail panel to make it wider or narrower (or click it and use the arrow keys). Double-click the line for the normal width. The width is remembered in this browser.

      
Overview
One quiet line (runs on, llmfit's own level, estimated or measured), then speed, memory, best file and context, and "Which file fits?" for every quantization (the verdict itself is at the top of the panel). When llmfit's planner (more safety room) rates the best file lower than the list, a yellow note says so and names the best file that runs well. Preview speed shows how fast text appears at that speed. "Why this result" lists llmfit's reasons.

      
KV cache from a real file
llmfit counts the memory for the context (the KV cache) exactly only when it knows a model's layers and head size. For about 4,900 models in its list it does not, and uses a rough rule. When TensorTailor reads a real GGUF file of such a model (your file in My models, or a file in the Files or Run tab), it fills in the missing values from the file's header. It never changes a value llmfit has, and skips a file that does not match. "Why this result" then says "KV cache counted from the GGUF header of …", and My models lists your models it did this for. Remembered in this browser.

      
Files
The real files on Hugging Face, one line per file (point at a long name for the full name; the copy button copies the download link), the file "best for this PC" first, and the verdict per file. Download saves a file into your folder and checks its SHA-256 at the end. Show SHA-256 of each file (under the table) shows the codes; click one to copy it.

      
Run
"LM Studio load settings for this PC": what to set in LM Studio's load dialog for this model (context length, GPU offload, flash attention, K/V cache, speculative decoding, remember settings), with the reason; point at a ? for what each setting does. Set it by hand in LM Studio (folded) says where these settings are in LM Studio. Load in LM Studio with these settings (when the model is in LM Studio and its server is on) first shows what will be sent, then asks LM Studio to load it: context length, flash attention, KV cache on the GPU and MTP. LM Studio's API cannot set GPU offload and K/V cache quantization, so LM Studio keeps its own setting for those. A model that is loaded already is unloaded first; other loaded models stay, unless you tick the box to unload them.

      
Run: Run it on this PC
Ready commands for LM Studio, llama.cpp or Ollama. With LM Studio, a model you already have shows your file first ("Your file in LM Studio · quant Q4_K_S"); llmfit's best file is named below it as an option: higher quality but less room for context, or smaller but lower quality. Below it: settings for AI agents (OpenCode, Codex).

      
Plan
llmfit's planner: the minimum and recommended hardware, which routes work here (GPU only, GPU + system RAM, CPU only) with a verdict and speed for each, and What would make it better?: for example "+1.7 GB VRAM → Runs well (llmfit: Good)". Below: whether a target speed is reached (the answer uses the route speeds above), how many chats fit at the same time, and the disk space for your best models.

    


    
Views (top) and keys

    

      
Models · My models · Battle · Downloads
Click to switch, or press 1 to 4. Esc always brings you back to Models.

      
My models
The models in your LM Studio (its server must be on: Developer tab → server on), with their size on disk, whether they are loaded, the verdict and speed here. The speed is for your file: llmfit counts its own best file (often another quant), so its range is scaled to the size of your file (point at the speed for both). Show opens the model in Models. "bundled with LM Studio" marks the embedding model that comes with LM Studio itself (it is not in your models folder; LM Studio uses it to search documents you add to a chat).

      
My models: your files
My models asks once for LM Studio's models folder (the same folder as for Downloads). TensorTailor matches each model to its file by size and reads only the start of the file. The Arch column then shows the layers and the maximum context ("65 layers · max 256K"); point at it for the KV cache figures (KV heads, head size, how many layers keep the whole context). For models that TensorTailor added itself ("live" or "from LM Studio"), llmfit then counts the KV cache exactly instead of roughly. When LM Studio does not name the quant, the file name tells it.

      
My models: MTP labels
MTP on / MTP off: LM Studio's own setting for a loaded model. MTP in file: the header of your model file has MTP layers. MTP (name): only the name says MTP; read your files to know for sure. "no MTP in file": the name says MTP, the file has none.

      
My models: summary cards
Five cards at the top: Models (and how many files TensorTailor read from your folder), On disk, Updates (files with a newer version on Hugging Face), Similar (space of models made from the same base model, and how much keeping one per group would free) and Measured (your real speed as a share of llmfit's estimate). The details are in the lines above the table and in the rows.

      
My models: Best setting
For a model matched to llmfit's list: the longest context that runs well, from llmfit's planner, the same advice as the LM Studio card in the Run tab ("Runs well up to 32K · 64K with KV Q8_0" = 32K normally, 64K with K and V cache at Q8_0). Capped at LM Studio's maximum. Not matched: a rough estimate from the file size. A loaded model with a longer context than fits gets a warning.

      
My models: Updates
After TensorTailor has read your models folder, it asks Hugging Face about each model file and its vision projector (the folder name is the repo; once a day, or Check again). update available: the file on Hugging Face now has another size or SHA-256; What changed ↗ opens its history. maybe changed: same size, but changed there after your file's date. "✓ up to date (size and date)": same size, not changed since. Check SHA-256 reads your whole file from disk (about a minute per 10 GB) and compares it exactly; then it says "(SHA-256, checked here)". Files you got with Downloads were already checked at the end of the download: "(SHA-256, checked at download)", no button needed. TensorTailor never replaces or deletes a file.

      
My models: Measure
Next to a model that is loaded in LM Studio. LM Studio writes about 256 tokens (10–30 seconds) and TensorTailor keeps the real speed next to the estimate: "measured 27 · est. 30–40 for your Q4_K_M", also in the detail panel's Speed. Point at it for the details (date, context, first token, the estimate then). The estimate is llmfit's, scaled to your own file when llmfit counts another quant. Measure never loads or unloads a model. With GPU measurements of models in llmfit's list, other models show "your PC: ~A–B" in the detail panel: llmfit's range times your measured share (the median).

      
My models: Similar models and disk space
Below the list: your models that come from the same base model (fine-tunes, uncensored versions, other quants), with their size on disk, verdict, best setting and folder (click to copy). Hugging Face says per repo which model it was made from; TensorTailor follows that up to the first model (remembered 30 days, Check again asks anew). It starts at the repo of the model's folder, else at the matched model (also a "from LM Studio" row named after its repo). Without an answer, the same design in the file header groups them. "Keeping only one of them would free up to …" = the group minus its smallest model. The label 3 similar in the list marks them. TensorTailor never deletes anything: remove a model in LM Studio or in File Explorer.

      
Battle
2 to 4 models (checkbox in the list, or Add to battle in Top picks) compete on this PC in four rounds: quality, speed, memory and context. One winner is named.

      
Downloads
Files you download (tab Files → Download). Choose LM Studio's models folder once; each file goes to the publisher's and repo's folder, so LM Studio sees it at once. Files come in parts, so Resume goes on after a crash; at the end the file is read back and its SHA-256 compared with Hugging Face's (Check again reads it once more). A vision model's projector (mmproj) is taken along. Remove from list never deletes a finished model file.

      
Favorites ★
Click the star next to a model (or press W) to make it a favorite. Only my favorites (filters) shows just those. My models shows the same stars for your LM Studio models that are matched to llmfit's list; click a star there to add or remove it too.

      
Token key (top right)
The key button left of the question mark: grey with no Hugging Face token, green with a small dot when a token is set. Click it to set, change or remove the token (only needed for gated models; it stays in this browser tab).

      
Tools (top right)
The button with three lines. Catalog: where the list comes from, and "Fetch new models" from Hugging Face. Hugging Face token: the same window as the key button. About and licenses. Light or dark (key T).

      
HF token
Read-only Hugging Face token for gated models. It stays only in this browser tab.

      
Keys
/ search · ↑ ↓ (or j k) move · C select for compare · W favorite (star) · T light or dark · ? help.
